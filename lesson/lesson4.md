# Lesson 4 — 지식 ②: 내 문서와 근거

수업 자료: [나니아랩 PBL 04](https://narnialab.duckdns.org:18231/session-04.html)

## 무엇을 배우고, 왜 배우는가

수업의 목표는 한 줄 메모를 넘어 실제 여러 페이지의 문서(PDF)를 구조적으로 읽어 적절한 크기의 조각(Chunk)으로 분할하고, 출처 메타데이터(파일명, 페이지 번호)와 함께 벡터 보관함(Chroma DB 등)에 저장한 뒤 질문 시 관련 조각과 원본 출처 쪽을 함께 제시하는 문서 검색 파이프라인을 구축하는 것이다.

이 수업을 거쳐 최종적으로 나오는 완성 결과물은 **‘긴 PDF 문서에서 문맥을 유지한 채 분할·색인하고, 질문에 대해 정확한 관련 문맥 조각과 함께 원본 페이지(출처 쪽)를 함께 명시하여 답변을 검증할 수 있게 하는 문서 기반 RAG 프로그램(`docs.py`)’**이다.

| 배우는 내용 | 배우는 이유 | 최종 결과물에서의 역할 |
|---|---|---|
| 문서(PDF) 텍스트 및 메타데이터 추출 | 실제 현업의 파일에서 본문 글뿐만 아니라 출처 확인을 위한 쪽 번호·문서명을 함께 가져온다. | 검색 결과의 신뢰성을 검증할 근거 출처 확보 |
| 텍스트 분할 (Chunking) 및 중첩 (Overlap) | 모델의 입력 길이 한계를 맞추고 문단 사이의 문맥이 잘려 유실되는 현상을 방지한다. | 의미 단위가 유지되는 검색 대상 텍스트 조각 생성 |
| 조각 크기 트레이드오프 이해 | 너무 작으면 문맥이 부족하고 너무 크면 관련 없는 내용이 섞여 검색 정확도가 떨어지는 점을 고려한다. | 문서 특성에 맞는 최적의 청크 크기 및 겹침 설정 |
| 벡터 데이터베이스 (보관함) 활용 | 대량의 문서 조각과 임베딩 벡터, 메타데이터를 파일로 영구 보관하고 효율적으로 색인·검색한다. | 문서 조각의 지속 보관 및 고속 유사도 검색 지원 |
| 답변-근거 문장-원본 쪽 추적 연결 | AI의 답변이 원본 문서의 몇 페이지 어느 구절에 기반했는지 사용자가 직접 열어 대조할 수 있게 한다. | 출처 투명성 및 사실 검증 기능 제공 |

수업의 기본 흐름은 다음과 같다.

```text
PDF 원본 문서 ──→ 쪽 단위 텍스트·메타데이터 추출 ──→ 중첩 포함 분할 (Chunking)
                                                           │
                                                           ↓
사용자 질문 ──→ 벡터 보관함 (Chroma 등) 검색 ←── 임베딩 벡터 + 메타데이터 보관
                    │
                    ↓
        관련 조각 원문 + 출처 쪽 번호
                    │
                    ↓
        질문 + 조각 원문 (RAG 결합)
                    │
        최종 답변 + 근거 출처 (페이지 번호) 제시
```

최종 결과물은 단순히 답만 알려주는 것이 아니라, 사용자가 “이 답이 원본 PDF 몇 쪽에서 나온 것인가?”를 직접 열어보고 사실 여부를 검증할 수 있는 출처 추적형 지식 검색 시스템으로 완성된다.
