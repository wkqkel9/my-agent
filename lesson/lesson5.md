# Lesson 5 — 손: 도구와 행동 반복 (ReAct·펑션 콜링)

수업 자료: [나니아랩 PBL 05](https://narnialab.duckdns.org:18231/session-05.html)

## 무엇을 배우고, 왜 배우는가

수업의 목표는 글만 생성하는 모델에 계산·조회 등 실제 작업을 수행하는 Python 함수(도구)를 연결하고, 문제 해결을 위해 생각(Thought)과 행동(Action), 관찰(Observation)을 반복하는 ReAct 패턴과 펑션 콜링(Function Calling) 방식을 익히며, 이를 웹 인터페이스에서 조작할 수 있도록 구현하는 것이다.

이 수업을 거쳐 최종적으로 나오는 완성 결과물은 **‘언어 모델이 사용자의 복합 질문을 분석하여 적절한 도구(Python 함수)를 인자값과 함께 호출하고, 도구 실행 결과를 다시 반영해 최종 결론을 내리며 웹 탭 화면으로 조작 가능한 도구 실행형 에이전트(`tools.py`, `app.py`)’**이다.

| 배우는 내용 | 배우는 이유 | 최종 결과물에서의 역할 |
|---|---|---|
| 도구 함수 정의 및 타입 힌트·설명 작성 | 모델이 도구의 역할, 입력 형식, 단위(예: 통화, 인원수)를 정확히 파악하여 올바른 인자를 넣게 한다. | 실행 가능한 작업(도구 스펙) 선언 |
| 펑션 콜링 (Function Calling) 규격 | 텍스트가 아닌 정형화된 JSON 형태로 함수명과 실행 인자를 모델이 결정하도록 한다. | 모델의 의도를 코드 실행 가능한 구조적 호출로 변환 |
| ReAct 패턴 (Thought → Action → Observation) | 한 번의 답변으로 끝나지 않고 도구의 실행 결과(관찰)를 바탕으로 다음 행동이나 최종 답을 추론한다. | 복잡한 다단계 연산 및 문제 해결 루프 수행 |
| 인간 개입 (Human-in-the-loop) 검토 | 결제, 데이터 삭제 등 되돌리기 어려운 위험한 도구 호출 전에 사람의 확인·승인 단계를 둔다. | 치명적인 오작동 방지 및 안전성 확보 |
| 웹 UI (다중 탭 인터페이스) 연동 | 터미널 명령어를 넘어 일반 사용자가 버튼과 입력창으로 각 기능을 직관적으로 실행할 수 있게 한다. | 도구 실행 및 결과를 시각화하는 사용자 인터페이스 |

수업의 기본 흐름은 다음과 같다.

```text
사용자 요청 ──→ [모델의 생각 (Thought)]
                        │
                        ↓
                 도구 호출 결정 (Action: 함수명 + 인자 JSON)
                        │
                        ↓
                 Python 실제 함수 실행
                        │
                        ↓
                 실행 결과 확인 (Observation)
                        │
                        ↓
              [다음 판단 또는 최종 답변 작성]
```

최종 결과물은 단순 텍스트 답변기가 아니라, 필요한 경우 직접 계산기를 두드리거나 외부 조회를 실행하여 최신·수치 정보를 얻고 이를 토대로 답하는 ‘행동하는 에이전트’로 완성된다.
